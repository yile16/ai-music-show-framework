# 模块 10：观众与社区系统

> 解决"观众只是数据来源，不是被设计的体验"的问题。
> 本模块定义观众是谁、如何激活他们、如何让他们留下来。

---

## 一、观众在框架中的角色转变

```text
旧视角（被动数据源）：          新视角（体验的共同创造者）：
                           
  观众                          观众
   │                            │
   ▼                            ▼
  观看                          观看 → 被钩子吸引
   │                            │
   ▼                            ▼
  数据点                        互动 → 评论/弹幕/投票
   │                            │
   ▼                            ▼
  结算输入                      二创 → 传播你的内容
                                │
                                ▼
                               留存 → 等你的下一期
                                │
                                ▼
                               参与 → 世界观的一部分
```

## 二、目标观众画像

### 2.1 核心受众（第一批要抓住的人）

| 标签 | 描述 |
|------|------|
| **年龄** | 18-30 岁（短视频主力） |
| **内容偏好** | 国风、神话改编、音乐、剧情向短视频 |
| **消费习惯** | 碎片时间刷短视频，通勤/睡前看中长内容 |
| **AI 态度** | 对 AI 内容好奇但不盲目追捧，更看重"好不好看" |
| **关键痛点** | "看过太多一样的东西""需要新鲜感""想被人理解" |
| **为什么关注你** | 神话人物+现代音乐+剧情，三个标签组合市面上没有 |

### 2.2 扩展受众（第二批辐射的人）

| 标签 | 描述 |
|------|------|
| **文化认同型** | 对西游/神话/历史有情结的 25-40 岁 |
| **音乐型** | 听国风 trap、独立音乐的乐迷 |
| **创作型** | 自己做 AI 内容、想看看别人怎么做的创作者 |
| **猎奇型** | 被"孙悟空唱 metal"这类反差吸引的路人 |

### 2.3 不要试图讨好的人

- "AI 内容都是垃圾"的纯抵制者
- 追求"还原原著"到每一个细节的原教旨主义者
- 只看纯娱乐、不接受任何"深度"的快餐内容消费者

## 三、观众生命周期设计

```text
┌───────────────────────────────────────────────────────┐
│  发现 (DISCOVER)                                       │
│  → 刷到你的视频 / 朋友分享 / 话题标签搜索               │
│  → 关键指标：开头 3 秒停留率                            │
│                                                       │
│  首次体验 (FIRST TASTE)                                │
│  → 看完一期完整内容，产生了第一个情绪反应                   │
│  → 关键指标：完播率 + 互动率                            │
│                                                       │
│  回访 (RETURN)                                         │
│  → 主动搜索/进入主页/等待下一期                          │
│  → 关键指标：粉丝增长 + "追更"评论数                     │
│                                                       │
│  参与 (ENGAGE)                                         │
│  → 评论/弹幕/投票/二创/分享                             │
│  → 关键指标：UGC 内容产生量                             │
│                                                       │
│  认同 (IDENTIFY)                                       │
│  → 成为"诸天音综"的粉丝，向朋友安利                       │
│  → 关键指标：自然传播率                                │
└───────────────────────────────────────────────────────┘
```

### 每个阶段的运营动作

#### 发现阶段

- 标题方向：反差 + 悬念 + 情绪标签（"五百年后他站起来了，但这次不是为了打架"）
- 封面原则：一个人的面部/剪影 + 高对比 + 不超过 5 个字
- 标签策略：3 个热门标签 + 2 个精准标签（#孙悟空 #AI音乐 #神话改编 + #诸天音综 #国风trap）
- 发布时间：工作日 12:00-13:00 或 18:00-19:00，周末 10:00-11:00

#### 首次体验阶段

- 开头 3 秒必须有视觉冲击（不能用黑屏/渐显/logo）
- 内容中间至少设计 1 个"想发弹幕"的瞬间
- 结尾必须在情绪高点结束，不能拖

#### 回访阶段

- 每期结尾明确暗示下一期（"下一棒，该你了"）
- 个人主页有清晰的内容合集/连续剧情线
- 评论区置顶"下一期想看谁？投票👇"

#### 参与阶段

- 评论区引导问题必须具体，不能是"大家觉得怎么样"
  - ❌ "大家觉得这期好看吗？"
  - ✅ "如果你心里也有一座五行山，它是什么？"
  - ✅ "下一期让哪吒来Battle，你们想看文斗还是武斗？"
- 投票功能用来做角色选择/曲风选择/对战结果

#### 认同阶段

- 设计可传播的"金句"（适合截图的台词）
- 设计可模仿的"名场面"（适合二创的桥段）
- "诸天音综"品牌关键词的持续重复

## 四、评论与弹幕的叙事化利用

### 4.1 弹幕是免费的内容团队

弹幕不是噪音，是实时反馈。好的弹幕反应可以直接成为下一期的内容。

**弹幕利用策略**：
- 在视频中预留"弹幕爆发点"（一个反转画面后留 1 秒空白，让弹幕飞）
- 下一期的开头可以引用上期弹幕（"上期有人说'猴子不需要舞台，舞台需要猴子'——你说得对"）
- 弹幕中的梗可以被角色在下一期中"回应"

### 4.2 评论区运营模板

**置顶评论**（发布后立即发）：

```text
模板 1（提问式）：
"这期的 [角色]，你觉得 [具体情绪/选择] 吗？"

模板 2（投票式）：
"下一期两个方向：
👍 [方向 A]
❤ [方向 B]
你们定。"

模板 3（补刀式）：
"补充一个细节：[一个观众可能没注意到的彩蛋]。发现的人扣 1。"
```

**回复策略**：
- 前 1 小时尽量回复每条评论（平台算法会加权）
- 有深度的长评论单独回复，不要复制粘贴
- 负面评论不争论，用"下一期会更注意"或幽默化解

## 五、跨期留存机制

### 5.1 内容层面的留存钩子

| 钩子类型 | 实现方式 | 示例 |
|---------|---------|------|
| 角色悬念 | 在当期中暗示另一个角色的到来 | 画面角落出现哪吒的剪影 |
| 系统悬念 | 系统面板弹出未完成的任务 | "检测到角色能量溢出。解锁条件：播放量 ≥ 10 万" |
| 关系悬念 | 两个角色的对话没有说完 | "下一期，我告诉你五行山底下到底是什么" |
| 榜单悬念 | 排名变化引发的竞争 | 某角色排名被超越，战书已下 |
| 隐藏彩蛋 | 需要多看几遍才能发现的细节 | 背景中某件道具属于下一期角色 |

### 5.2 运营层面的留存策略

- **固定更新日**：设定一个每周固定的发布日期，培养观众习惯
- **预告帖**：更新前 1 天发预告（一张图+一句话），预热期待
- **系列命名**：每期标题带上系列标识（[诸天音综 #002]），方便搜索

## 六、观众反馈 → 内容迭代闭环

```text
发布内容
    │
    ▼
收集数据 + 评论 + 弹幕（1-3 天）
    │
    ▼
填写迭代日志（iteration-log-template.md）
    │
    ├── 数据好的部分 → 沉淀为"有效策略库"
    ├── 数据差的部分 → 根因分析 → 调整方案
    └── 观众提出的想法 → 评估可行性 → 可能成为下期创意
    │
    ▼
下一期方案中明确体现"上期反馈的回应"
    │
    ▼
在下一期中用一句话暗示"这是你们说的"
  → 观众会觉得自己是创作的一部分
```

### 反馈处理原则

1. **观众说的"问题"通常是准的，但观众提出的"解决方案"通常不对。** 意思是：相信观众的感受（"这段无聊"），但不要照搬观众的建议（"你应该加一段打戏"）。
2. **10 个同样的意见 = 必须处理。1 个独特的意见 = 可能是天才也可能是噪音。**
3. **沉默的多数人比发声的少数人更重要。** 如果播放量高但评论少，不是坏事——可能内容太好看忘了评论。

## 七、社区增长飞轮

```text
         好内容
           │
    ┌──────┴──────┐
    ▼              ▼
  观众互动      二创传播
    │              │
    ├── 评论/弹幕   ├── 截图分享
    ├── 投票参与   ├── 音乐引用
    └── 梗的诞生   └── 模仿/配音
    │              │
    └──────┬───────┘
           ▼
      更多人发现
           │
           ▼
      更多角色邀请
           │
           ▼
      更好的内容
           │
        (循环)
```

### 飞轮的启动策略

- **前 3 期是生死线**：前 3 期不追求完美，追求"每期比上一期好一个明显的地方"
- **第 1 期目标**：让人知道"这个东西存在"
- **第 2 期目标**：让人知道"这个东西不是一次性的"  
- **第 3 期目标**：让人知道"这个东西会越来越好看"

## 八、度量体系

### 核心指标（每期必看）

| 指标 | 健康值 | 警戒值 | 说明 |
|------|--------|--------|------|
| 完播率 | > 40% | < 20% | 低于 20% 说明内容本身有问题 |
| 点赞率 | > 3% | < 1% | 低于 1% 说明情绪共鸣不足 |
| 评论率 | > 0.5% | < 0.1% | 低于 0.1% 说明没有互动触发 |
| 分享率 | > 1% | < 0.3% | 分享是最强的认可 |
| 粉丝转化率 | > 2% | < 0.5% | 多少人看完愿意关注你 |

### 增长指标（每三期汇总）

| 指标 | 说明 |
|------|------|
| 粉丝增长率 | 三期之间粉丝数变化 |
| 自然流量占比 | 搜索/推荐/标签带来的流量 vs 外部引流 |
| 平均观看时长 | 单期和系列的变化趋势 |
| 系列完播率 | 看了第 1 期的人有多少看了第 3 期 |
